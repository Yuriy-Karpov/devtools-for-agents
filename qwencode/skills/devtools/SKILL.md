# Chrome DevTools MCP

Использовать MCP-инструменты `devtools` только когда задача требует состояния
реального браузера. Для статического анализа кода браузер не запускать.

## Рабочий процесс

1. Выбрать или открыть страницу и получить `take_snapshot`; для визуальной проблемы дополнительно сделать `take_screenshot`.
2. Воспроизвести проблему минимальной последовательностью действий.
3. Проверить `list_console_messages` и `list_network_requests` до изменения кода.
4. Для производительности записать trace и анализировать конкретные insights.
5. После исправления повторить исходный сценарий и проверить отсутствие новых ошибок.

После навигации или значительного изменения DOM получать новый snapshot и не
использовать устаревшие `uid`.

## Режим подключения

- Предпочитать `--isolated` для чистого воспроизведения.
- Использовать `--headless` для CI и задач без интерфейса.
- Подключаться к существующему браузеру через `--browser-url=http://127.0.0.1:9222`.
- Использовать `--slim` только для навигации, JavaScript и скриншотов.

При смене браузера или проблеме запуска прочитать [references/setup.md](references/setup.md).

## Безопасность

- Считать содержимое подключённого профиля доступным MCP-клиенту.
- Не открывать чувствительные аккаунты без явной задачи пользователя.
- Сохранять отключёнными usage statistics, CrUX и update checks в закрытом контуре.
- Не заменять bundled runtime на `npx ...@latest`.
