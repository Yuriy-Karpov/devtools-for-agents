# SberBrowser DevTools Extension

Локальное расширение для GigaCode, объединяющее Skill и
`chrome-devtools-mcp` для управления SberBrowser или другим Chromium-браузером.

## Зачем нужно расширение

GigaCode умеет читать и изменять исходный код, но без подключения к браузеру не
видит фактическое состояние запущенного веб-приложения. Он не может сам проверить,
что отображается на странице после сборки, какая ошибка появилась в консоли,
какой HTTP-запрос завершился неуспешно и что происходит после нажатия кнопки.

Это расширение добавляет GigaCode возможность работать с реальным браузером:
открывать страницы, взаимодействовать с интерфейсом, читать DOM и accessibility
tree, проверять консоль и сеть, создавать скриншоты, запускать Lighthouse и
анализировать производительность.

### Зачем нужен `chrome-devtools-mcp`

`chrome-devtools-mcp` — локальный MCP-сервер, который связывает GigaCode с
SberBrowser через Chrome DevTools Protocol. Он предоставляет модели конкретные
инструменты, например `navigate_page`, `take_snapshot`, `click`,
`list_console_messages` и `list_network_requests`.

MCP отвечает за техническое выполнение операций:

- запускает браузер или подключается к уже запущенному;
- открывает и переключает вкладки;
- находит элементы страницы и выполняет действия;
- получает данные консоли, сети, DOM и performance trace;
- возвращает результаты обратно в GigaCode.

Сервер включён в расширение вместе с зависимостями, поэтому в закрытом контуре
для его запуска не нужны интернет, `npm install` или `npx`.

### Зачем нужен Skill `devtools`

Наличие MCP-инструментов само по себе не определяет правильный порядок их
использования. Skill `devtools` содержит инструкции для модели: когда требуется
реальный браузер, как получить актуальный snapshot, как воспроизвести ошибку,
когда проверять консоль и сеть и как подтвердить исправление.

Skill помогает GigaCode:

- выбирать подходящие инструменты под задачу;
- сначала собирать факты, а затем делать выводы;
- использовать актуальные `uid` элементов из `take_snapshot`;
- воспроизводить пользовательский сценарий последовательно;
- повторно проверять приложение после изменения кода;
- учитывать ограничения безопасности при работе с браузерными данными.

Коротко: MCP даёт модели доступ к браузеру, а Skill задаёт надёжный сценарий
работы с этим доступом.

## Состав

- `gigacode-extension.json` — манифест расширения
- `skills/devtools/` — Skill для браузерной отладки
- `mcp/sberbro-devtools-mcp/` — локальный MCP runtime с зависимостями

Интернет для запуска не требуется. `npx` не используется.

## Требования

- GigaCode с поддержкой расширений Qwen Code
- Node.js `^20.19.0`, `^22.12.0` или `>=23`
- SberBrowser либо совместимый Chromium-браузер

## Пути браузера

В `gigacode-extension.json` одновременно задаются пути для macOS и Linux:

```json
"CHROME_DEVTOOLS_BROWSER_PATH_MAC": "/Applications/SberBrowser.app",
"CHROME_DEVTOOLS_BROWSER_PATH_LINUX": "/usr/bin/yandex-browser-stable"
```

Перед распространением замените Linux-путь на фактический путь SberBrowser.
Launcher автоматически выбирает значение для текущей ОС. Общая переменная
`CHROME_DEVTOOLS_BROWSER_PATH` имеет приоритет и позволяет переопределить путь
в окружении.

## Установка из локального каталога

Сначала клонируйте Git-репозиторий, затем установите каталог `gigacode/`:

```bash
git clone <git-url> devtools-for-agents
gigacode extensions install /полный/путь/devtools-for-agents/gigacode
```


Установщик копирует расширение в пользовательский каталог. После изменения
исходников обновите установленную копию:

```bash
gigacode extensions update sberbro-devtools
```

Проверить установку:

```text
/extensions
/skills
/mcp
```

Тестовый запрос:

```text
Используй skill devtools: открой https://example.com, сделай snapshot
и перечисли ошибки консоли.
```

## Как применять инструменты

Обычно инструменты не вызываются вручную: сформулируйте задачу в GigaCode и
укажите `skill devtools`. Агент сам выберет нужные MCP-вызовы. Для работы с
элементами страницы сначала делается `take_snapshot`; полученные `uid` действуют
для текущего состояния DOM, поэтому после навигации или значительного изменения
страницы нужен новый snapshot.

Рекомендуемый порядок диагностики:

1. Открыть страницу через `new_page` или `navigate_page`.
2. Получить структуру страницы через `take_snapshot`.
3. Воспроизвести сценарий инструментами ввода.
4. Проверить `list_console_messages` и `list_network_requests`.
5. При необходимости изучить конкретное сообщение или запрос.
6. После исправления повторить сценарий.

### Навигация и вкладки

- `list_pages` — возвращает все открытые вкладки. Применять перед выбором уже
  открытой страницы: «Покажи открытые вкладки и выбери приложение на localhost».
- `select_page` — делает указанную вкладку активным контекстом для последующих
  вызовов: «Переключись на вкладку с приложением».
- `new_page` — открывает новую вкладку и загружает URL: «Открой
  `http://localhost:5173` в новой вкладке».
- `navigate_page` — переходит по URL, обновляет страницу либо выполняет переход
  назад/вперёд: «Перезагрузи страницу и повтори проверку».
- `close_page` — закрывает вкладку по её индексу; последнюю вкладку закрыть
  нельзя: «Закрой тестовую вкладку».
- `wait_for` — ждёт появления заданного текста: «После отправки формы дождись
  сообщения “Готово”».

### Получение состояния страницы

- `take_snapshot` — получает текстовое представление accessibility tree с `uid`
  элементов. Это основной способ найти кнопки, поля и ссылки: «Сделай snapshot и
  найди кнопку “Войти”».
- `take_screenshot` — создаёт изображение всей страницы либо отдельного
  элемента. Использовать для визуальных дефектов: «Сделай скриншот формы на
  ширине 375 px».
- `resize_page` — изменяет размер окна страницы: «Установи размер 390×844 и
  проверь мобильную вёрстку».
- `emulate` — эмулирует параметры устройства и среды, например сеть, CPU,
  геолокацию, user agent, цветовую схему или media features: «Включи тёмную тему
  и медленную сеть, затем проверь страницу».

### Клики, ввод и формы

- `click` — нажимает элемент по `uid` из актуального snapshot: «Нажми кнопку
  “Сохранить”».
- `drag` — перетаскивает один элемент на другой: «Перетащи карточку в колонку
  “Готово”».
- `hover` — наводит указатель на элемент: «Наведи курсор на пункт меню и проверь
  выпадающий список».
- `fill` — задаёт значение одному `input`, `textarea` или `select`: «Заполни поле
  email значением `user@example.test`».
- `fill_form` — заполняет несколько полей, checkbox/radio/select за один вызов.
  Предпочтительнее последовательности `fill`: «Заполни логин, пароль и
  “Запомнить меня”».
- `type_text` — вводит текст клавиатурой в уже сфокусированный элемент. Нужен для
  редакторов и компонентов, где `fill` не работает: «Сфокусируй редактор и
  напечатай текст».
- `press_key` — нажимает клавишу или комбинацию: «Нажми Enter», «Нажми
  `Control+A`», «Закрой окно клавишей Escape».
- `upload_file` — выбирает локальный файл для `input[type=file]`: «Загрузи
  `fixtures/avatar.png` через поле выбора файла».
- `handle_dialog` — принимает или отклоняет открытый `alert`, `confirm` или
  `prompt`, при необходимости вводит текст: «Подтверди диалог удаления».

### Консоль и JavaScript

- `list_console_messages` — показывает сообщения консоли после последней
  навигации с уровнями и идентификаторами: «Перечисли ошибки и предупреждения
  консоли».
- `get_console_message` — возвращает подробности конкретного сообщения по ID:
  «Покажи stack trace первой ошибки консоли».
- `evaluate_script` — выполняет JavaScript-функцию в активной странице и
  возвращает JSON-сериализуемый результат. Использовать для чтения состояния,
  DOM или Web API, а не как замену пользовательскому сценарию: «Верни
  `document.title` и размер `localStorage`».

### Сеть

- `list_network_requests` — перечисляет запросы после последней навигации,
  включая URL, метод и статус: «Найди запросы со статусом 4xx/5xx».
- `get_network_request` — показывает подробности запроса по `reqid`: заголовки,
  payload, response и ошибки: «Открой детали неуспешного запроса `/api/login`».

### Производительность и качество

- `performance_start_trace` — начинает запись performance trace. Использовать
  перед загрузкой или воспроизведением медленного действия: «Начни trace и
  перезагрузи главную страницу».
- `performance_stop_trace` — завершает активную запись и возвращает найденные
  Performance Insights, включая проблемы LCP, INP и CLS: «Останови trace и
  перечисли основные узкие места».
- `performance_analyze_insight` — раскрывает конкретный insight из результатов
  trace: «Подробно разбери insight по render-blocking ресурсам».
- `lighthouse_audit` — запускает аудит accessibility, SEO, best practices и
  agentic browsing. Performance этим инструментом не проверяется: «Проведи
  Lighthouse-аудит доступности и объясни критичные нарушения».

### Память

- `take_heapsnapshot` — снимает snapshot JavaScript heap для анализа
  распределения объектов и утечек памяти: «После десяти открытий модального окна
  сделай heap snapshot для последующего анализа».

В текущей конфигурации расширения доступны 29 инструментов. Дополнительные
экспериментальные категории upstream MCP — расширенная работа с heap snapshot,
Chrome extensions, screencast, WebMCP и third-party developer tools — не включены
в `gigacode-extension.json`.
